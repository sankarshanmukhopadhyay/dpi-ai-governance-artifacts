# Documentation architecture

The rendered site is organized around remediation tasks rather than repository folders.

## Primary journey

1. **Start here** — resolve what you are trying to improve.
2. **Operator playbook** — turn a capability mapping into deployment-specific implementation and evidence.
3. **Remediation catalog** — inspect capability coverage and reusable assets.
4. **Operational packs** — use broader implementation bundles where appropriate.
5. **Controls and evidence** — inspect control IDs, schemas, evidence bundles, and conformance materials.
6. **Governance and reference** — authority, normativity, controlled documents, standards mappings, and maintainer material.

## Cross-repository responsibility

The Lab owns findings, gap normalization, and closure assessment. This repository owns reusable remediation assets and their coverage maturity. The rendered sites cross-link at the handoff without collapsing those responsibilities.

## Site versus repository

The repository remains the canonical source for machine-readable registries, schemas, templates, test vectors, and controlled documents. Pages is the curated reading and navigation layer.
